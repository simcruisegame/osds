# OSDS 3.0 plan

**In short**
- 3.0 is a drivers' game that lets you drive anywhere in the US: five cars that feel like the real ones, a world that looks like the place you're in, a Garage to make the car yours, and famous race tracks.
- The week runs 2026-11-22 to 2026-11-29. The feature cut-off is Thursday evening. The release candidate and the full release test are on Friday. The Owner playtests at the weekend, and 3.0 ships only on the Owner's go.
- All work is tracked in the GitHub milestone [3.0](https://github.com/simcruisegame/osds/milestone/1). Each area has a Spec issue and Tickets under it.

## How we work (Matt Pocock's skills)

1. A grill with docs. The decisions go into `GLOSSARY.md` and ADRs.
2. A Spec.
3. Tickets with blocking links, worked by one Thread per area, each in its own Worktree.
4. `/tdd` at the agreed seams.
5. `/code-review` on two axes, Standards and Spec.
6. A PR body with a merge-danger call.
7. The Coordinator runs the fast tier and merges two-way doors. One-way doors go to the Owner.
8. `/retro`: each mechanical mistake becomes an automated check.

## Testing rules

- **Look:** every test, capture and realism score runs at **Ultra**, visibly, so the Owner can watch. High is the frame-rate gate (45+ fps in the seat).
- **Launch and look:** nobody calls a change working without opening the frames. The `art-director` agent reviews any change to the look.
- **Places:** every change is judged at Random US places, not only on Hero roads.
- **Done for 3.0:** no P0 or P1 bug in the final run (Random US places, Hero roads, Race tracks, all five cars).

## Budget rules for agents

- No context window over 200k tokens, for any thread or subagent.
- Sonnet for the threads, at most one subagent each. Builds and tests run in the background, and agents wait for the notice instead of polling.
- At most four threads at a time. The single build lock and the 5-hour usage limit are the real bottlenecks.
